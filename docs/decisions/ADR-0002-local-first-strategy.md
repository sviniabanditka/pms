# ADR-0002 — Local-first: Этап А (optimistic UI + delta-sync) в MVP

- Статус: accepted
- Дата: 2026-06-27
- Связано: §12.1, §7.4 спеки

## Контекст

§12.1 — строить ли «настоящий» local-first сразу (ElectricSQL/PowerSync/Zero) или
поэтапно. Это самое затратное решение продукта (§7.4): скорость уровня Linear даёт
не «быстрый API», а локальная модель данных.

## Решение

**Этап А в MVP**: optimistic UI + WS delta-sync поверх собственного Postgres.
Апгрейд на специализированный sync-движок — отдельная веха после MVP, без
переписывания ядра.

## Почему

- Меньше риска и привязки к вендору на самом раннем этапе.
- Этап А уже даёт «локальное» ощущение: чтения/записи к локальному стору мгновенны, сеть — фоновая сверка.
- Полноценный offline на больших объёмах (Этап Б) не нужен для MVP-ценности.

## Механика Этапа А (резюме; детальный протокол — в `02-architecture/sync-protocol.md`)

- Первичная загрузка среза доступных команд → нормализованный стор (Pinia) + IndexedDB.
- Мутации оптимистичны: применяются локально, отправляются командами с client-generated UUID (идемпотентность), несут `baseVersion`.
- Сервер пишет в `change_log`, бампает `version`, публикует дельту сущности в канал workspace/team; клиенты применяют, если новее.
- Догон после оффлайна: реконнект → `since=<cursor>` из `change_log` → доигрывание своей очереди отложенных мутаций.
- Конфликты: per-field LWW по `version`/`updated_at` для структурных полей; свободный текст — LWW по всему полю в MVP, CRDT (Yjs) — отдельная веха.

## Что закладываем СЕЙЧАС ради дешёвого апгрейда на Этап Б

- **Клиентский стор за интерфейсом `StoreGateway`** — транспорт/движок подменяемы.
- **Единый `command bus`** — все мутации через него, доменная логика не знает транспорта.
- Стабильная схема дельт и курсоров (`change_log`) — переносима на Electric/PowerSync.

## Последствия

- M0 включает скелет синка (каналы/дельты на уровне инфраструктуры), доводка — M7.
- `version` на каждой синкуемой сущности + `change_log` — обязательны с самого начала.
- Контрактные тесты на идемпотентность и догон — часть критического пути.
