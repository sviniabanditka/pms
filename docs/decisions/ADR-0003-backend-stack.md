# ADR-0003 — Бэкенд-стек: контракты, БД, очереди, WS

- Статус: accepted
- Дата: 2026-06-27
- Связано: §7.2 спеки

Фиксируем спорные развилки §7.2. Остальное стека спеки (Go, chi, PostgreSQL,
Redis, slog, OTel, golang-migrate, OpenSearch/RabbitMQ позже) принято как есть.

## Решения

| # | Развилка | Выбор | Отклонение от спеки |
|---|---|---|---|
| S1 | Контракты фронт↔бек | **ConnectRPC** (proto → Go + TS) | нет (дефолт спеки) |
| S2 | Доступ к БД | **bun** (один инструмент: query-builder + лёгкий ORM, raw SQL по месту) | да — спека предлагала sqlc/ent |
| S3 | Очереди задач | **River** (Postgres-backed) | да — спека ставила asynq дефолтом |
| S4 | WebSocket | **coder/websocket** | нет (дефолт спеки) |

## Почему

**S1 ConnectRPC.** Команды — RPC-формы (`CreateIssue`, не CRUD на таблицу); Filter AST
переносится как payload, а не как транспорт. proto = единый источник Go- и TS-типов,
серверный стриминг под поток дельт. REST/GraphQL проигрывают по форме API (стриминг,
дублирование собственного языка запросов).

**S2 bun.** Один инструмент покрывает и статику, и динамику: компилятор Filter AST → SQL
строится bun query-builder'ом, без второго инструмента. Вложенные команды = recursive CTE
(пишем явным SQL через bun), custom fields = JSONB-операторы. Платим типобезопасностью
относительно sqlc — осознанно, ради единого инструмента.

**S3 River.** Транзакционный enqueue: джоба ставится в той же транзакции, что и доменная
мутация → нет dual-write между мутацией и нотификацией/индексацией. Redis остаётся под
pub/sub, presence, cache. Потолок: тяжёлые штормы индексации грузят БД — на MVP-масштабе
пренебрежимо; если упрёмся, выносим индексацию на отдельный пул/Redis-очередь.

**S4 coder/websocket.** Context-aware, net/http-native, чистый API. Потолок: сотни тысяч
соединений на инстанс → пересмотр на gobwas/ws.

## Последствия

- buf/proto toolchain в репо; кодген TS-клиента в CI.
- River-таблицы в той же БД; миграции River под golang-migrate/Atlas.
- bun-модели как слой доступа в каждом доменном пакете; чужие таблицы не трогаем напрямую (§7.3).
- S5 (фронт-библиотеки: графики/календарь/DnD/виртуализация/grid) — решается на этапе `03-frontend`, не блокирует.
