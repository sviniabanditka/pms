# ADR-0004 — Скоуп MVP: команды, custom fields, renderers, доки

- Статус: accepted
- Дата: 2026-06-27
- Связано: §12.2, §12.3, §12.4, §12.9 спеки

## Решения

### #2 Семантика вложенных команд — подтверждена

- Issue принадлежит **ровно одной** команде (владелец).
- Опциональный **rollup** в родителя через флаг во View (`options.rollupDescendants`).
- Членство **наследуется** для public-дочерних команд; private-дочерние требуют явного членства.
- Вариант «issue в нескольких командах» — отвергнут.

Следствие для домена: простой атомарный счётчик нумерации на команду; права предсказуемы
(issue наследует видимость своей команды). Краевые случаи (перемещение issue между командами,
глубина вложенности, private внутри public) — детализируются в `01-domain/teams.md`.

### #3 Custom fields в MVP — база + relationship

- В MVP: `text`, `number`, `date`, `checkbox`, `select`, `multiselect`, `url`, `people`, **`relationship`** (ссылка на другой issue/запись).
- Отложено (post-MVP): `formula`, `rollup` — вычислимые поля, тянут вычисления в фильтр/таблицу.

Следствие: query-движок поддерживает предикаты по `relationship` (eq/in по target-id, isSet),
но НЕ вычисляемые выражения. `money`/`rating` — частные случаи number/select, могут стартовать урезанно.

### #4 Timeline/Gantt — ранний v2, не MVP

- MVP renderers: **Board, List, Table, Calendar**.
- Timeline (полосы start→target, зависимости-стрелки, вехи) — первый кандидат раннего v2.
- Контракт `ViewRenderer` (§6.3) уже допускает добавление без изменения модели View — нулевая цена отсрочки.

### #9 CRDT-доки — v2 или позже

- MVP: доки и описания — одиночное редактирование, **LWW по полю/документу**.
- Совместное редактирование (Yjs + серверная персистенция) — изолированная веха, не раньше v2.

## Последствия для критического пути MVP

- Query-движок (Filter AST) проектируется под базовые + relationship поля; вычислимые — точка расширения, не реализуется.
- 4 renderer'а вместо 5; пятый — чистое добавление позже.
- Доки в MVP не требуют CRDT-инфраструктуры — экономия на M7.
