# Мануальный QA-чеклист

Полный прогон функций. Держится **актуальным**: при каждом добавлении/изменении —
дописывать сюда. Помечай ✅/❌ по ходу.

## Запуск
```bash
make up && make migrate          # инфра + миграции (если не подняты)
cd backend && PORT=8080 go run ./cmd/server   # бэкенд :8080
cd frontend && npm run dev                    # фронт :3000
```
Открыть http://localhost:3000 · тест-юзер `bob@example.com` / `supersecret`.

## 1. Auth (M0)
- [ ] Открыть `/login` без сессии → редирект на login.
- [ ] Register нового email → попадаешь в приложение (авто-логин).
- [ ] Register тем же email повторно → ошибка «email already registered».
- [ ] Logout (⎋ внизу левого рейла) → редирект на login.
- [ ] Login с верным паролем → вход; с неверным → «invalid credentials».
- [ ] Reload после входа → остаёшься залогинен (сессия в Redis + токен в localStorage).

## 2. Топбар + разделы рейла (M0 + M6 + M7)
- [ ] **Верхняя панель**: слева свитчер воркспейса (имя+аватар, дропдаун), по центру поле **Search ⌘K** (клик/⌘K → палитра), справа ✉ с бейджем непрочитанных.
- [ ] Левый рейл (узкий): **разделы** `◫ Dashboard`, `✉ Inbox`, `☰ Tasks` (активный подсвечен). Переключение меняет сайдбар и main.
- [ ] Раздел **Tasks** → сайдбар с командами/проектами/циклами/полями, main = задачи.
- [ ] Раздел **Dashboard** → сайдбар со списком дашбордов, main = виджеты.
- [ ] Раздел **Inbox** → main = список нотификаций.
- [ ] **⚙ (настройка разделов)** внизу рейла → панель: чекбокс видимости + ↑↓ порядок. Спрятал раздел → исчезает из рейла; поменял порядок → применяется. Reload — сохраняется (per-user `sections_config`).
- [ ] Аватар-кнопка вверху левого рейла (буква воркспейса) → клик открывает дропдаун.
- [ ] В дропдауне — список твоих воркспейсов; активный подсвечен.
- [ ] Выбор другого воркспейса → teams и issues меняются на его данные (не остаются от прошлого).
- [ ] «＋ New workspace» → форма в сайдбаре; создать (slug+name) → появляется и выбирается.
- [ ] Создать пустой воркспейс → открывается без ошибок (пустые списки).
- [ ] Имя активного воркспейса видно вверху контекстного сайдбара.

## 3. Teams (M0)
- [ ] Дерево команд в сайдбаре; вложенные — с отступом.
- [ ] Создать root-команду: parent=«— root team —», KEY (заглавные, ≤10), name → «+».
- [ ] Создать вложенную: выбрать родителя в дропдауне → создать → появляется с отступом под родителем.
- [ ] Дубль KEY в воркспейсе → ошибка.
- [ ] Невалидный KEY (строчные/пробел/>10) → ошибка.
- [ ] У новой команды есть дефолтные статусы (видно при выборе команды).

## 4. Issues — List (M1)
- [ ] Выбрать команду → справа список issues, сгруппированный по статусам (счётчик в каждой группе).
- [ ] Создать issue: «+ New issue» в группе → Enter → появляется с `KEY-N` (номер растёт).
- [ ] Inline-правка title (изменить → blur/Enter) сохраняется.
- [ ] Сменить priority дропдауном.
- [ ] Сменить status дропдауном → issue переезжает в другую группу.
- [ ] Archive (✕ на ховере) → issue исчезает из списка.

## 5. Issues — Board (M2)
- [ ] Переключатель List/Board в шапке.
- [ ] Board: колонки = статусы, карточки = issues по порядку.
- [ ] Drag карточку в другую колонку → статус меняется (проверка: переключись на List — статус новый).
- [ ] Drag внутри колонки между карточками → порядок меняется и сохраняется после reload.
- [ ] «+ New» внизу колонки создаёт issue в этом статусе.

## 6. Filter (M3)
- [ ] Search по title → список/борд фильтруется мгновенно.
- [ ] Чипы priority (мультивыбор) → показываются только выбранные приоритеты.
- [ ] «clear» сбрасывает фильтр.
- [ ] Фильтр применяется и в List, и в Board.

## 7. Saved Views (M3)
- [ ] Настроить фильтр → «Save view» → ввести имя → появляется ★ чип.
- [ ] Клик по ★ чипу → грузит сохранённый фильтр + layout (List/Board).
- [ ] Reload → сохранённые views на месте (bootstrap).

## 8. Issue detail · Sub-issues · Relations (M4 ч.1)
- [ ] Клик по `KEY-N` (в List или на карточке Board) → справа открывается панель деталей.
- [ ] В панели: правка title, смена status/priority.
- [ ] **Sub-issues**: «+ Add sub-issue» → создаётся дочерняя (в команде родителя); видна в списке.
- [ ] Прогресс детей: счётчик done/total в панели и на карточке Board (⌥ n/m); завершённая дочерняя — зачёркнута.
- [ ] **Relations**: выбрать тип (blocks/blocked_by/related/duplicate/duplicate_of) + ввести `KEY-N` цели → «+» → связь добавляется.
- [ ] Открыть целевую issue → связь видна **зеркально** (blocks ↔ blocked by).
- [ ] Удалить связь (✕ на ховере).
- [ ] Невалидная цель (`KEY-N` не найден) → ошибка; связь на саму себя → отклоняется.
- [ ] Клик по identifier внутри панели (sub/relation) → переключает панель на ту issue.

## 9. Дерево команд: Issues/Cycles/Docs/Views (M4/M7)
- [ ] Tasks-сайдбар = дерево команд (вложенные с отступом). Клик по команде разворачивает под-пункты.
- [ ] Под командой: **Issues**, **Cycles** (Current/Upcoming), **Docs** (вложенное дерево), **Views**, Fields.
- [ ] **Issues** → main список/борд команды.
- [ ] **Cycles** разворачивается → Current/Upcoming; «+» с датами создаёт; клик → фильтр + burndown.
- [ ] Detail-панель issue: селект **Cycle** (Project убран как сущность).
- [ ] (Projects удалены из продукта — секции нет.)
- [ ] **Burndown**: полоса показывает Scope/Started/Completed + SVG (пунктир = идеал, линия = факт). Заверши issue в цикле (статус Done) → факт-линия снижается. «close» убирает полосу.
- [ ] Невалидные даты цикла (конец раньше начала) → ошибка.

## 10. Realtime (M0/M2)

- [ ] Активный фильтр применяется и в календаре.

## 12. Custom fields (M6 ч.1)
- [ ] Сайдбар (команда выбрана): секция **Fields** → имя + тип (text/number/date/checkbox/select/multiselect/url); для select/multiselect — опции через запятую → «+» → поле появляется в списке.
- [ ] Detail-панель issue: секция **Fields** с инпутом по типу; задать значение → держится (reload).
- [ ] select → дропдаун опций; multiselect → чипы-тогглы; checkbox → галка; number/date/text/url → инпут.
- [ ] Снять значение (очистить) → удаляется.

## 13. Dashboards & Widgets (M6 ч.2) — раздел рейла ◫ Dashboard
- [ ] Рейл → **◫ Dashboard** → сайдбар: список дашбордов + «New dashboard» → «+» → создаётся, открывается в main.
- [ ] Дашборд в main: карточка **Add widget** → тип (note/stat/view/chart) + title.
  - [ ] **note**: текст → виджет с текстом.
  - [ ] **stat**: «all issues» или приоритет → число (count). Поменяй issues → reload, число меняется.
  - [ ] **view**: выбрать сохранённый view → виджет со списком его issues.
  - [ ] **chart**: заглушка «позже».
- [ ] ✕ на виджете удаляет.
- [ ] Клик по команде в сайдбаре выходит из дашборда обратно к issues.

## 14. Cmd-K / поиск (M7 ч.1)
- [ ] **⌘K / Ctrl+K** открывает палитру; Esc закрывает; клик по фону закрывает.

- [ ] ↑/↓ двигают выбор, Enter переходит; клик мышью тоже.
- [ ] Переход: issue→detail-панель в нужной команде; team→Tasks+команда; project→фильтр; dashboard→раздел Dashboard; view→применён.

## 15. Inbox / нотификации (M7 ч.2)

- [ ] Генерация: другой пользователь назначает issue на тебя → `assigned`; меняет статус твоего/созданного тобой issue → `state_changed`. (Соло свои действия не нотифицируют — нужен 2-й юзер; для проверки можно подсеять.)

## 16. Docs — вложенное дерево (M7 ч.3)

## Известные ограничения (не баги — см. debt-ledger)
- UI голый (нет Nuxt UI компонентов/иконок) — D14.
- Группировка только по статусу — D22.
- Assignee/labels/даты не правятся в UI — D11/D10/D12.
- Дропдаун воркспейсов без click-outside (закрывается выбором/созданием).
- Дельта триггерит полный refresh среза — D7.

## 19. Chats (раздел)
- [ ] Рейл → **Chats**. Сайдбар: Channels (+ создать) и Direct messages (список юзеров воркспейса).
- [ ] «+» у Channels или глобальный «+ → New channel» → модалка → канал появляется, открывается.
- [ ] Клик по каналу → главная: сообщения + композер. Отправка (Enter) — сообщение появляется.
- [ ] Markdown: `# заголовок`, `**bold**`, `_italic_`, `` `code` ``, списки `-`, ссылки — рендерятся.
- [ ] Композер: тулбар B/I/code/link/list оборачивает выделение; toggle Preview показывает рендер; Shift+Enter — перенос.
- [ ] Клик по юзеру в Direct messages → создаётся/открывается личный чат (дедуп пары).
- [ ] Реалтайм: во втором табе сообщение в открытом канале появляется без перезагрузки (WS-дельта → точечный рефетч).
- [ ] **Edit**: ховер по своему сообщению → ✎ → правка inline (Enter save, Esc cancel) → «(edited)».
- [ ] **Delete**: ховер → 🗑 (только своё) → «(message deleted)».
- [ ] **Reactions**: ховер → 😊 → пикер эмодзи; чип реакции с счётчиком; клик по чипу — toggle (своя подсвечена).
- [ ] **Threads**: ховер → reply-в-тред / клик по «N replies» → правая плавающая панель: родитель + реплаи + композер; счётчик растёт.
- [ ] **Typing**: во 2-м табе при наборе — «X typing…» над композером (гаснет ~4с).
- [ ] **Бесконечный скролл**: прокрутка вверх подгружает старые (before-курсор), позиция сохраняется.

## 20. Comments (в detail-панели задачи)

- [ ] Realtime: коммент во 2-м табе на открытой задаче появляется без reload (WS-дельта comment).
